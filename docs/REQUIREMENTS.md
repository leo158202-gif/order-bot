# 需求与有效规则

- 一个自然月一本表，每天一个日期sheet；按原消息北京时间自然日登记，不以处理时间代替。
- H列物流恒空。承运商、自提、到付/现付、代收、取件配送等明确物流信息合并到G地址；先保留原地址和物流，再清空旧logistics字段，不能重复追加或猜默认值。新单、改单、重试和导出一致，历史行不批量迁移。
- 金标是业务对照标准；只有用户明确追加才能扩充规则。未证厚度、款式、配件不得补猜，保留待核。金标配对不等于产品正确，检查点一致不等于业务通过。
- 特殊来源群只收原文明确包含“本地”的订单；实际部署需配置自己获授权的群范围。其它启用群仍按正常范围处理。
- 同单姓名或地址末尾四位方括号数字属于虚拟号分机，先迁移到有效手机号，再清理展示。冲突留待核，不将长单号当分机。
- 修改、补充、取消更新唯一同群原单，禁止凭引用或咨询生成新单；来源不明或跨群混入不得写表。
- 定时事件身份为schedule_id与原定触发时刻；手动操作有独立身份。同身份重试去重，独立操作不得因内容相同而跳过。暂停期间不得私自恢复发送。
- 通知只包含订单数、待核数、新增、修正及当月当日完整链接；不发客户明细。
- 缺证不能计正确；“我方少”和“我方多”分开报告。相同证据累计最多3轮，不因重启、脚本版本或交接重置。
